Working 

The project was developed in multiple stages using Wokwi simulation, ESP32 programming, cloud communication, and IoT dashboard integration. The first step was creating the hardware setup in the Wokwi simulation platform. An ESP32 microcontroller was selected as the main processing unit, and multiple sensors were connected to it, including the DHT22 sensor for temperature and humidity monitoring, MQ2 sensor for smoke and gas detection, PIR sensor for motion detection, LDR sensor for light intensity monitoring, and an OLED display for local output visualization. Proper GPIO connections were made between the ESP32 and each sensor according to their analog or digital communication requirements.

After completing the hardware connections, the ESP32 was programmed using Arduino C++ code inside the Wokwi environment. Required libraries such as DHTesp, Adafruit SSD1306, Adafruit GFX, WiFi, MQTT, and Blynk libraries were installed and included in the code. The ESP32 was programmed to continuously read values from all connected sensors and display important information such as temperature, humidity, motion status, and system condition on the OLED display. Threshold conditions were also implemented in the code so that if abnormal values such as high temperature or excessive gas levels were detected, the system would automatically switch to ALERT mode and activate a warning LED.

In the next stage, cloud communication was implemented using the MQTT protocol and HiveMQ public broker. The ESP32 was connected to WiFi and programmed to publish sensor readings to MQTT topics using the PubSubClient library. Different topics were created for each sensor parameter such as temperature, humidity, gas level, light level, motion detection, and system status. HiveMQ acted as the cloud message broker that received and distributed the published sensor data. MQTT dashboard tools were then used to subscribe to these topics and verify that live telemetry data was being transmitted successfully from the ESP32 to the cloud platform.

After understanding MQTT communication, the project was upgraded further by integrating the Blynk IoT platform to create a professional real-time dashboard. A new Blynk template and device were created, and virtual datastreams were configured for each sensor parameter. The ESP32 code was modified to include Blynk cloud communication using the Blynk authentication token and template information. Sensor data was then transmitted directly from the ESP32 to the Blynk cloud platform through WiFi. The Blynk web dashboard was designed using gauges, labels, and indicators to display live sensor values and system status in real time.

Finally, the completed system functioned as a cloud-connected server room monitoring and safety platform. The ESP32 continuously monitored environmental conditions using multiple sensors, processed the data locally, displayed important information on the OLED screen, and transmitted telemetry data to the cloud dashboard. Whenever unsafe conditions such as overheating or gas leakage occurred, the system generated alert conditions that were reflected on both the local display and the online dashboard. The project successfully demonstrated embedded systems programming, IoT communication, cloud telemetry, sensor interfacing, and real-time remote monitoring using a simulated but industry-relevant architecture.
